## Controlled corpus: Parcel Quotes

The keyword baseline uses `postgres-keyword-v1`, K=5, 15 queries and 14 queries with
expected evidence. Recall measures fully covered references; reciprocal rank measures
the first overlapping expected span. A partial span can yield positive RR but zero
strict recall. The no-evidence case is excluded from both averages.

| Metric | Historical measured result |
| --- | ---: |
| Macro Recall@5 | 0.5714285714 |
| MRR@5 | 0.6369047619 |
| Mean retrieval latency | 1.610272 ms |
| Median retrieval latency | 1.579 ms |
| p95 retrieval latency | 2.25875 ms |
| Timed samples | 150 |

The baseline records commit `11687c956a11e50995dfca18e3b62e0a57347e96`, Java 21.0.7,
macOS/aarch64, PostgreSQL 17.11, two warmups per query, and a two-connection pool.
These are historical local retrieval timings, not current API/model latency targets.

Known failures include incomplete multi-reference coverage for validation-to-pricing
questions and missed implementation evidence for the shipping question. The M1.7
single-question comparison reported KEYWORD `INSUFFICIENT_EVIDENCE` (7,337 ms), VECTOR
`SUPPORTED` (10,558 ms), and HYBRID `SUPPORTED` (7,836 ms), with implementation at rank 5
for Vector/Hybrid. These observations do not establish aggregate strategy superiority.

M1.6 reported **$300 instead of 300 cents**, and **$800 instead of 800 cents**, despite
valid citation identities. The v2 rerun still failed semantic support. A correct source
reference does not repair an incorrect interpretation.

M1.8 implements versioned capture, offline grading, and attributed human review. The
[M1.8 reporting acceptance record](../architecture/evaluation-reporting.md#verification-scope)
records a six-execution replay with zero execution failures, five applicable valid
citation identities, and one abstention. Its replay selected no human review, leaving
all seven claims NOT_REVIEWED. Other maintainer-reported reviews are not silently
merged into it. No aggregate live Vector/Hybrid Recall/MRR score is inferred here.

## Fresh release screenshot observation

On **2026-10-19**, installed Chrome **155.0.8059.85** submitted the same DDIP question
once through the live React UI with VECTOR. It returned **PARTIALLY_SUPPORTED**,
two claims and two citations, **12,991 ms** API duration and **12,091 ms** model duration,
with 2,440 input and 250 output tokens reported. This is a separate execution from
the prior 11.101-second run, not a repeated latency benchmark.

The UI resolved the actual constructor citation in `BoundedProcessRunner.java`
(lines 23–26). A fresh comparison against the pinned Git blob matched the original
inclusive excerpt including line terminators, Git blob ID, source SHA-256, and content
SHA-256. The test citation points to `BoundedProcessRunnerTest.java` lines 30–34.
Only the constructor citation was freshly source-compared during screenshot capture;
the earlier run recorded checks for both citations.

The constructor supports the semaphore-initialization claim. The selected test
configuration does not demonstrate production timeout enforcement or a universal
10-second runtime limit. The model's own uncertainty makes that limitation visible.
This distinction is part of the demo, not a reason to relabel the answer SUPPORTED.

## Release limitations

- Small controlled corpus; no held-out, cross-repository accuracy claim.
- Three initial real-repository questions plus one release capture, not a broad benchmark.
- Local timings with no workload distribution, hardware-normalized comparison, or SLA.
- Historical raw private reports are not fully redistributed; the JSON is a selected extract.
- Current UI is visually accepted; tagging, hosted CI review, artifact version alignment,
  and GitHub release publication remain maintainer-controlled. The Maven artifact still
  declares `0.0.1-SNAPSHOT`; this documentation task does not change build versions.
